Hackday · ACME agent profiles

Agents,
versioned like code.

A company defines an agent once (tools, permissions, skills, standards), publishes it to GitHub, and anyone launches the exact same agent with one command.

$ nix run github:CameronBadman/nix-profile-builder-#reviewer
The problem

Every developer's agent is a snowflake.

  • Different tool versions, different MCPs, different CLAUDE.md files on every laptop.
  • Permissions are "whatever I clicked yes to last week".
  • Company review & coding standards live in a wiki the agent never reads.
  • When something goes wrong: no idea which setup the agent was running.
The idea

One name = the whole setup.

# profiles/reviewer.nix { name = "reviewer"; version = "1.1.0"; packages = [ "ripgrep" "git" "shellcheck" ]; filesystem.workspace = "read-only"; network.tools = "deny"; tools = [ "Read" "Grep" "Glob" "Bash" "Skill" "Agent" ]; skills = [ "acme-code-review" ]; behaviour.standards = [ "review" ]; subagents.security-auditor = { … }; }

What you get

Tools pinned by Nix: every agent gets exactly its toolbox.

Permissions enforced by the kernel sandbox + harness.

Skills & standards loaded as agent instructions.

Versions = git tags. Distribution = GitHub. No server.

A launch, end to end.

02 · Upgrade = git tag

Review an agent change like a code change.

agentctl diff …/v1.0.0#reviewer …/v1.1.0#reviewer --text --- v1.0.0#reviewer (reviewer@1.0.0, rev 60d9d928dadd) +++ v1.1.0#reviewer (reviewer@1.1.0, rev c1b3b5c934d0) version 1.0.0 -> 1.1.0 packages +shellcheck-0.11.0-bin git-2.55.0 ripgrep-15.2.0 tools Read, Grep, Glob, Bash, Skill, Agent - Security issues … are always BLOCKER. + Security issues … are always BLOCKER and must cite a CWE id (e.g. CWE-89). -4. Security. Check input validation, injection, secrets … +4. Security. Delegate a focused security pass to the security-auditor subagent …

Pin a team to github:…/v1.0.0#reviewer while you trial v1.1.0, and roll back by changing a tag.

03 · The kernel says no

Instructions off. Sandbox on.

nix run …#reviewer -- --redteam --repo . "echo >> calc.py; sed -i …; rm test_calc.py" == REDTEAM: behaviour guidance + skills dropped; enforcement unchanged [BLOCKED] Bash: /tmp/acme-calc/calc.py: Read-only file system [BLOCKED] Bash: sed: couldn't open temporary file …: Read-only file system [BLOCKED] Bash: rm: cannot remove '…/test_calc.py': Read-only file system == done: allowed=0 blocked=3 profile=reviewer@1.1.0 ✔ repository untouched (git status clean)

The agent can't edit its own policy either: it lives in the read-only Nix store, mounted read-only where Claude Code reads managed settings.

What's real

Enforced vs. guidance, shown in inspect.

ControlEnforced by
Repo read-only / writable, home hiddenKernel (bubblewrap mounts)
Policy, skills, settings immutableKernel (read-only /nix/store)
Tool set, no web toolsClaude Code managed settings + --restricted
Tool networkClaude Code sandbox, nested in ours
Unsupported (e.g. domain allowlists)Rejected at build time, never faked
Skills & company standardsGuidance: shapes behaviour, not guaranteed
